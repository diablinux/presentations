# Observability: Knowing When Things Break

In production, the goal is not just to keep services running, but to understand their internal state at any given moment. This requires a three-pronged approach:

**The Pillars of Observability:**
1.  **Metrics (What is happening?):** Aggregated numerical data (CPU usage, request latency, error rates). Prometheus is the standard tool here.
2.  **Logs (Why did it happen?):** Discrete, timestamped events generated by the application. Centralized logging (e.g., ELK stack) is crucial for debugging.
3.  **Traces (How did it happen?):** Following a single request as it flows through multiple microservices. This is essential for diagnosing latency in distributed systems.
